# 인포러시 (inforush)

**큰 주제 하나**만 넣으면, AI가 웹 검색으로 그 주제의 **최신 정보**를 훑어
지금 사람들이 가장 많이 찾아볼 만한 글감을 골라, 품질 기준을 지킨 정보성 글과 썸네일을 만들어
**네이버 블로그에 정한 개수만큼 임시저장**해 주는 로컬 대시보드입니다.

워드프레스용 [머니러시](https://github.com/jettyy/moneywordpress)에서
**글을 올리는 곳만** 바꾼 것입니다. 주제를 고르는 방식, 대기열, 자료 조사,
글의 형식, 품질 규칙, 썸네일 만드는 방식은 전부 그대로입니다.

| | 머니러시 (워드프레스) | 인포러시 (네이버) |
|---|---|---|
| 큰 주제 → 글감 발굴 | — | **똑같습니다** |
| 주문 대기열 · 목표 개수 | — | **똑같습니다** |
| 자료 조사 · 품질 검사 · 썸네일 | — | **똑같습니다** |
| 접속 | REST API + 응용 프로그램 비밀번호 | **Playwright 로 띄운 실제 브라우저** |
| 로그인 | 비밀번호를 프로그램이 보관 | **사용자가 창에서 직접 로그인** |
| 본문 넣는 법 | API 로 한 번에 전송 | **에디터에 조각으로 나눠 붙여넣기** |
| 본문 형식 | 구텐베르크 블록 마크업 | **인라인 style 을 박은 HTML** |
| 분류 | 카테고리 ID 로 지정 | **발행할 때 사람이 고릅니다** |
| 태그 | 워드프레스 태그로 등록 | **글 끝에 `#태그` 줄**로 붙임 |
| 글 사이 대기 | 20~60초 | **30~90초** (네이버는 연속 자동화에 더 민감합니다) |
| 실행 위치 | 어디서나 | **사용자 PC** (로그인 창이 필요합니다) |

- 주제 발굴: **웹 검색**으로 최신 정보를 훑고 관심도 점수를 매겨 고릅니다
- 글 생성: `claude -p` (Claude Code CLI 헤드리스 모드) → **구독 요금제 그대로 사용**, 토큰 종량 과금 없음
- 자료 조사: 고른 주제마다 **다시 웹 검색**으로 사실과 출처를 모아 그것만 근거로 씁니다
- 품질 준수: 분량·문체·표·구조를 **프로그램이 직접 검사**하고, 어긋나면 그 항목만 짚어 다시 쓰게 함
- 발행은 하지 않습니다. **임시저장까지만** 하고, 사실 확인과 발행은 사람이 합니다.

## 어떻게 도는가

큰 주제와 개수를 넣고 **[확인]** 을 누르면 **대기열**에 들어갑니다.
누르는 즉시 입력칸이 비워지므로, 검색이 도는 동안에도 다음 주제를 계속 넣을 수 있습니다.

```
[확인] "전기차" 5건      ─┐
[확인] "청년 지원금" 3건  ├─ 대기열 (넣은 순서대로)
[확인] "부동산 정책" 5건  ─┘
        │
        ▼  실행기가 앞에서부터 하나씩 가져다 씁니다
┌─ 주문 "전기차" 5건 ────────────────────────────────────┐
│  ├─ [발굴]  웹 검색 6회 → 후보 8건 → 관심도 순으로 채택   │
│  │          "전기차 공공충전요금 8월부터 5단계로 개편…" 90점 │
│  │          "2026년이 마지막? 취득세·개소세 감면 일몰…"  87점 │
│  ├─ [조사]  주제마다 다시 검색해 사실·출처를 모음          │
│  ├─ [집필]  검색을 끄고 그 자료만 보고 씀 → 품질 검사      │
│  ├─ [썸네일] 제목·띠·뱃지가 들어간 그림                   │
│  └─ [저장]  네이버 에디터에 옮겨 적고 **임시저장**         │
│      └─ 5건이 저장될 때까지 반복. 주제가 떨어지면 다시 발굴 │
└────────────────────────────────────────────────────────┘
        │
        ▼  개수를 채우면 다음 주문으로
┌─ 주문 "청년 지원금" 3건 ─ ... ─┐
```

한 건이 실패하면 세지 않고 다음 주제로 넘어갑니다. **성공한 것만 개수에 셉니다.**
5건을 원했으면 네이버 임시저장 목록에 5건이 올라갑니다.

한 주문이 개수를 채우면 넉넉히 받아 둔 나머지 주제는 **건너뜀**으로 정리하고
다음 주문으로 넘어갑니다. 그래야 "5건만" 이라는 약속이 지켜집니다.

## 주제를 어떻게 고르는가

"최신 정보"만으로는 부족합니다. 어제 나온 뉴스라도 아무도 안 찾는 것이 있고,
사람들이 실제로 검색창에 치는 것은 따로 있습니다. 그래서 발굴 단계에서
**조회수가 나오는 조건**을 순서대로 일러 줍니다.

| 우선순위 | 어떤 것 |
|---|---|
| 1 | **지금 막 바뀐 것** — 제도 개편, 새 정책, 요금·금리 변동, 시행일이 정해진 것 |
| 2 | **내 돈·시간·자격이 걸린 것** — 신청 방법, 지원 대상, 지급액, 마감일, 과태료 |
| 3 | **검색창에 그대로 칠 만한 것** — 사람들이 입력할 말이 분명한 소재 |
| 4 | **아직 정리된 글이 적은 것** — 뉴스는 많은데 "그래서 어떻게 하냐" 가 없는 소재 |
| 5 | **기한이 임박한 것** — 이번 달, 이번 분기에 마감되거나 시작되는 것 |

반대로 고르지 못하게 막는 것도 있습니다. 하루 지나면 아무도 안 찾는 가십,
연예인 사생활, 정치적 진영 다툼, 확인되지 않은 의혹, **의료·금융에서 효과나 수익을
단정하는 소재**, **특정 업체·상품을 밀어 주는 소재**, 검색으로 근거를 못 찾은 소재입니다.
뒤의 두 항목이 네이버판에서 더 중요합니다. 네이버는 광고성으로 분류된 글을
검색에서 잘 안 보여주고, 근거가 없는 주제는 집필 단계에서 어차피 거절당해 호출만 버립니다.

고른 주제에는 **0~100점의 관심도 점수**와 "지금 왜 이걸 찾는지" 한 줄이 붙습니다.
작업표의 **관심도** 열에 점수가 뜨고, 마우스를 올리면 이유와 검색어가 보입니다.

### 제목을 어떻게 쓰게 하는가

키워드가 아니라 **그대로 글 제목이 될 한 문장**으로 받습니다.

- 나쁜 예: `전기차 보조금`
- 좋은 예: `2026년 전기차 보조금, 지역별로 얼마나 달라졌을까`

항목을 나열하는 글이면 개수를 문장에 넣게 합니다(`TOP 5`, `7가지`).
개수가 들어가면 기존 규칙대로 항목마다 **상세 설명 · 자격 요건 · 활용 분야 ·
장단점 · 준비 팁**을 세부 소제목으로 나눠 씁니다.

`충격`, `경악`, `이것만 알면` 같은 낚시성 표현은 프롬프트로 막고, 그래도 나오면
**프로그램이 제목에서 걸러냅니다.** 네이버 검색에서 불리한 표현이기 때문입니다.

### 같은 주제를 두 번 쓰지 않습니다

큰 주제 하나로 며칠씩 계속 돌리는 도구라서, 이게 없으면 사흘째부터 비슷한 글만 나옵니다.

- 발굴한 주제는 `data/topic-history.json` 에 남고, 다음 발굴 프롬프트에 **"이건 이미 썼다"** 로 들어갑니다
- 작업 목록을 비워도 기록은 남습니다. 그래야 어제 쓴 주제를 오늘 다시 안 고릅니다
- 글쓰기가 실패한 주제도 기록합니다. 안 그러면 매번 같은 주제를 골라 와 매번 실패합니다
- 돌아온 목록 안에서도 겹치는 것을 버립니다. 비교할 때 **공백과 기호를 무시**해서
  `국가기술자격증 TOP 5!` 와 `국가기술자격증top5` 를 같은 것으로 봅니다
- 같은 제도라도 다른 각도(신청 방법 / 달라진 점 / 대상별 차이 / 흔한 실수)로 잡으라고 일러 줍니다

처음부터 다시 쓰고 싶으면 2번 칸의 **[발굴 기록 지우기]** 를 누르세요.

### 그래도 글은 무조건 나옵니다

위 장치는 **새 소재를 우선하려는 것이지, 글을 막으려는 것이 아닙니다.**
비슷한 큰 주제를 여러 개 걸어두면(대학 순위 / 대학 서열 / 학과 순위 …)
기록이 쌓일수록 "이미 쓴 주제" 에 전부 걸려서 아무 것도 못 고르게 됩니다.
실제로 주문 20건이 전부 `새 주제를 찾지 못했습니다` 로 멈춘 적이 있습니다.

그래서 조건을 한 단계씩 풀어 가며 **반드시 뭐라도 건져 옵니다.**

| 단계 | 조건 |
|---|---|
| 1 | 원래 조건 — 이미 쓴 주제 제외 + 관심도 점수 하한 |
| 2 | **이미 쓴 주제 허용** (대기열에 이미 있는 것만 제외) |
| 3 | **관심도 점수 하한까지 해제** |
| 4 | 그래도 없으면 **큰 주제로 글감을 직접 만듦** (`2026년 대학 순위 총정리` 처럼) |

조건을 풀어서 골랐으면 대기열 줄에 그 이유가 같이 표시되고 로그에도 남습니다.
같은 소재를 다른 각도로 쓰게 되므로, 그런 표시가 자주 보이면 큰 주제를
넓히거나 [발굴 기록 지우기] 를 눌러 주세요.

## 쓰는 법

1. **네이버 로그인** — [네이버 로그인 창 열기]를 누르면 브라우저 창이 뜹니다.
   아이디·비밀번호(+2단계 인증)를 그 창에 직접 입력하세요.
   로그인이 확인되면 세션이 `data/browser-profile/` 에 저장되고, 다음부터는 재로그인이 필요 없습니다
2. **큰 주제와 개수** — 2번 칸에 넣고 **[확인]** (Enter 키로도 됩니다)
3. **바로 다음 주제** — 칸이 비워져 있으니 이어서 넣으면 됩니다. 넣은 만큼 줄을 섭니다
4. **확인** — 네이버 글쓰기 화면 오른쪽 위 **[저장]** 목록에서 내용과 사실관계를 확인하고 발행하세요

[확인] 을 누르면 **실행도 같이 시작됩니다.** [실행] 버튼을 따로 누르지 않아도 됩니다.
(로그인이 안 돼 있으면 대기열에만 넣어 두고, 로그인한 뒤 [실행]을 누르면 이어서 돕니다)

대기열은 2번 칸 아래에 줄지어 보입니다. 아직 시작 안 한 주문은 **[취소]** 로 뺄 수 있고,
진행 중인 주문을 취소하면 아직 안 쓴 주제는 건너뜀으로 정리됩니다.

| 버튼 | 무엇을 지우나 |
|---|---|
| 각 줄의 **[취소]** | 그 주문 하나 |
| **[끝난 주문 정리]** | 이미 끝난(완료·실패) 주문만. 진행 중·대기 중인 것은 그대로 |
| **[대기열 전체 삭제]** | 진행 중인 것까지 **주문 전부**. 한 줄씩 취소할 필요가 없습니다 |

전체 삭제는 되돌릴 수 없어서 몇 건이 지워지는지 보여주고 한 번 묻습니다.
그 주문들이 이미 찾아둔 주제도 같이 건너뜀으로 정리합니다. (주문만 지우면
작업 목록에 남은 주제가 계속 써져서, 지웠는데도 글이 올라갑니다)
**이미 임시저장된 글은 지워지지 않습니다.** 직접 넣은 주제도 남습니다.

> **처음 써 보신다면 [미리 보기만] 을 한 번 눌러보세요.** 대기열에 넣지 않고
> 어떤 글감이 나오는지만 보여줍니다. 큰 주제가 너무 넓거나 너무 좁으면 거기서 드러납니다.

### 큰 주제는 얼마나 넓게

| 큰 주제 | 어떤가 |
|---|---|
| `정부 지원금` | 조금 넓습니다. 소재는 많지만 성격이 제각각이라 블로그 색이 흐려집니다 |
| `청년 정부 지원금` | **적당합니다.** 소재가 꾸준히 나오고 방향이 한결같습니다 |
| `2026년 청년월세지원 소득 기준` | 너무 좁습니다. 두세 편 쓰면 더 쓸 것이 없습니다 |

네이버는 **한 블로그가 한 주제를 꾸준히 다루는 것**을 더 쳐줍니다(C-Rank).
큰 주제를 이것저것 섞기보다 한두 개로 좁혀 꾸준히 돌리는 편이 유리합니다.

소재가 떨어지면 로그에 `새로 쓸 만한 주제를 찾지 못했습니다` 가 뜨고 **그 주문만** 접은 뒤
대기열의 다음 주문으로 넘어갑니다.

## 2번 칸 설정

| 항목 | 설명 |
|---|---|
| 큰 주제 | 이것만 넣으면 됩니다. 개별 글 제목을 적는 칸이 **아닙니다** |
| 임시저장할 개수 | 이만큼 **저장에 성공하면** 그 주문이 끝납니다. 실패·건너뜀은 세지 않습니다 |
| 한 번에 찾아올 주제 수 | 주제가 떨어질 때마다 이만큼씩. 발굴은 검색이 여러 번 도는 호출이라 몇 개씩 받는 편이 빠릅니다 |
| 최신 기준 (일) | 며칠 이내에 나온 정보를 우선할지. 기본 30일 |
| 관심도 점수 하한 | 이보다 낮은 주제는 버립니다. 기본 40. **주제를 못 찾으면 이 값을 낮추세요** |
| **대기열이 비면 큰 주제를 알아서 이어 붙이기** | 아래 "끊김 없이 계속 쓰기" 참고. 기본 꺼짐 |
| 발굴 검색 횟수 상한 | 한 번 발굴할 때 검색을 몇 번까지. 기본 6회 |

### 끊김 없이 계속 쓰기 (자동 이어가기)

큰 주제를 계속 넣어 주지 않아도 멈추지 않게 하는 기능입니다.
2번 칸의 **[대기열이 비면 큰 주제를 알아서 이어 붙이기]** 를 켜면,
대기열이 다 비었을 때 실행을 끝내지 않고 이렇게 합니다.

```
대기열이 비었다
   │
   ▼  지금까지 쓴 큰 주제를 씨앗으로 주고
      "결이 이어지는 분야를 더 찾아줘" 라고 물어본다
   │   (예: 대학 입시를 써 왔으면 → 취업, 자격증, 학자금 쪽)
   ▼
큰 주제 3건을 대기열에 이어 붙인다 (각각 지금 개수 칸의 값만큼)
   │
   ▼  평소처럼 글감을 찾아 글을 쓰고 임시저장
      다 쓰면 다시 위로
```

- 씨앗은 `data/topic-history.json` 에 남은 **큰 주제**들입니다. 처음 켜서 기록이
  비어 있으면 한국 독자가 꾸준히 찾는 분야에서 알아서 고릅니다
- **이미 쓰고 있는 분야는 빼고** 받습니다. 같은 글만 계속 나오지 않게요
- 개별 글 제목이 아니라 **글감을 5~10편 뽑을 수 있는 넓은 분야**를 달라고 합니다
- AI 가 새 분야를 못 줘도 **멈추지 않습니다.** 지금까지 쓰던 분야로 이어 갑니다
  (같은 분야라도 글감은 각도를 바꿔 가며 새로 만들어집니다)
- 이 항목을 켜 두면 **대기열이 텅 비어 있어도 [실행] 이 됩니다.** 큰 주제를
  하나도 넣지 않고 그냥 돌려도 알아서 분야를 정해 씁니다

> **켜 두면 사람이 끄기 전까지 멈추지 않습니다.** 구독 사용량과 네이버
> 임시저장 개수가 계속 늘어납니다. 자는 동안 돌리실 거면 켜 두시고,
> 아침에 임시저장 목록을 한 번 확인하시는 편을 권합니다.
> 네이버는 한 블로그가 한 주제를 꾸준히 다루는 것을 더 쳐주므로,
> 분야가 너무 넓게 퍼지는 것 같으면 꺼 두고 직접 넣으시는 편이 낫습니다.

### 넣는 방법은 세 가지입니다

2번 칸에 버튼이 세 개 있습니다. 어디까지 정해 두고 싶은지에 따라 고르세요.

| 넣는 곳 | 무엇을 넣나 | 제목은 누가 정하나 | 언제 쓰나 |
|---|---|---|---|
| **큰 주제** (기본) | 분야 하나 (`전기차 보조금`) | AI 가 검색해서 글감과 제목을 다 정합니다 | 알아서 계속 쓰게 두고 싶을 때 |
| **직접 주제 추가** | 글감 문장 | AI 가 그 글감으로 제목을 다듬습니다 | 소재는 정했고 제목은 맡기고 싶을 때 |
| **제목 그대로 쓰기** | 완성된 제목 | **적어준 문장 그대로** 씁니다 | 제목까지 정해 두고 그 제목에 맞춰 쓰게 하고 싶을 때 |

셋 다 **한 줄에 하나씩 쭉 붙여넣으면 줄마다 따로따로** 들어갑니다.
직접 넣은 것이 발굴한 주제보다 먼저 처리됩니다.

### 제목 그대로 쓰기

여기 넣은 문장은 **글 제목이 됩니다.** AI 가 제목을 다시 짓지 않습니다.

```
2026년 수도권 대학 순위 TOP 50 총정리
대기업 평균 연봉 순위 TOP 30, 어디가 가장 높을까
전세 계약 전에 반드시 확인해야 하는 서류 7가지
```

이렇게 세 줄을 붙여넣으면 글 세 편이 목록에 들어가고, 각각 **그 제목 그대로**
저장됩니다. 작업표에는 `제목 고정` 표시가 붙습니다.

제목만 따라가고 내용이 딴 데로 가면 소용이 없으므로, 본문도 **그 제목이
약속한 내용**을 지키도록 요구합니다.

- 제목에 개수가 있으면(`TOP 50`, `7가지`) 본문에서 그 개수를 채웁니다
- 제목이 비교를 약속하면 비교를 하고, 방법을 약속하면 방법을 씁니다
- 제목에 쓰인 말이 본문 앞쪽에도 들어갑니다 (검색에 그대로 걸리라고)

> 개수를 다 못 채워도 **찾은 만큼 1위부터 순위를 매겨** 냅니다.
> (위 "목표를 못 채워도 순위는 반드시 매깁니다" 참고)

## 왜 브라우저로 올리는가

네이버에는 블로그 글쓰기 공개 API 가 없습니다. 그래서 실제 브라우저를 띄워
스마트에디터 ONE 에 사람이 하듯 옮겨 적는 방법밖에 없습니다.
워드프레스의 REST API 보다 느리고 잘 깨지므로, 깨지는 자리마다 대비를 넣었습니다.

| 깨지는 자리 | 대비 |
|---|---|
| 에디터 클래스 이름이 바뀜 | 선택자를 `src/naver/selectors.js` 한 곳에 후보 여러 개로 모아 둠. 자동화가 깨지면 대부분 여기만 고치면 됩니다 |
| 글쓰기 주소가 안 먹힘 | 주소 3개를 차례로 시도하고, 그래도 안 되면 블로그 화면의 글쓰기 버튼을 직접 누름 |
| 붙여넣기 거절 | 합성 paste → 실제 클립보드(Ctrl+V) → 평문 타이핑 순으로 내려감 |
| 표가 통째로 사라짐 | 한 번에 → 20행씩 조각내서 → **표를 그림으로 그려 파일 업로드** |
| 붙여넣기가 허공에 뿌려짐 | 조각을 붙이기 전마다 **커서를 본문 끝에 다시 놓고**, 편집 영역을 못 잡으면 그 자리에서 실패로 멈춤 |
| 일부만 들어가고 나머지가 사라짐 | 넣으려던 분량의 60% 가 실제로 들어갔는지 조각마다 확인. 일부만 들어갔으면 되돌린 뒤 다음 방법으로 (되돌리지 않으면 같은 글이 두 번 들어갑니다) |
| 본문이 텅 빈 채 저장됨 | 저장 직전에 전체 글자 수를 다시 재서, 넣으려던 양의 절반에 못 미치거나 300자도 안 되면 **저장하지 않고 재시도** |
| 출처가 기사 카드로 바뀜 | 본문에 주소를 아예 넣지 않음 (위 "자료 조사" 참고) |
| 정렬하다 본문이 날아감 | 정렬은 Ctrl+A 로 전체를 선택하고 하는 동작이라, 정렬 뒤 글자 수가 줄었으면 저장하지 않음 |
| 글자가 다 회색으로 나옴 | 모든 문단과 셀에 글자색을 직접 박음 (비우면 앞 블록 색을 물려받습니다) |
| 문단이 앞 문단에 들러붙음 | 조각마다 맨 앞에 빈 문단을 하나 붙여 그게 대신 합쳐지게 함 |
| 가운데 정렬로 들어감 | 저장 직전에 본문 전체를 왼쪽 정렬로 한 번에 맞춤 |
| 무엇이 막혔는지 모름 | 실패한 순간의 화면을 `data/screenshots/` 에 저장하고 경로를 작업표에 남김 |

표가 실제로 들어갔는지는 **에디터 안의 `<table>` 개수를 세어** 확인합니다.
"글자가 좀 늘었나" 만 보면 100행짜리 표가 통째로 잘려도 성공으로 치기 때문입니다.

## 네이버라서 다른 것 (미리 알아두실 점)

- **카테고리와 공개 설정은 지정하지 않습니다.** 네이버는 그 칸들이 [발행] 레이어 안에 있어서,
  임시저장만 하는 이 프로그램은 건드리지 않습니다. 발행하실 때 직접 고르세요.
- **태그는 발행창이 아니라 글 끝에 `#태그` 줄로 붙습니다.** 같은 이유입니다.
  발행할 때 태그 칸에 옮겨 넣으시면 검색 노출에 더 유리합니다.
- **대표 이미지는 따로 지정하지 않아도 됩니다.** 네이버는 글의 첫 번째 이미지를 대표로 씁니다.
  그래서 썸네일을 도입부 바로 뒤에 넣습니다.
- **글 주소는 정할 수 없습니다.** 머니러시의 영문 슬러그 기능은 여기서 뺐습니다.
- **임시저장한 글을 바로 여는 주소가 없습니다.** 작업표의 [임시저장 목록] 을 누르면
  글쓰기 화면이 열리고, 오른쪽 위 **[저장]** 을 누르면 저장된 글 목록이 나옵니다.
- **이 프로그램은 사용자 PC에서 실행해야 합니다.** 네이버 로그인에 실제 브라우저 창이 필요하고,
  세션도 사용자 PC에 저장되기 때문입니다.

## 멈추지 않고, 그렇다고 영원히 돌지도 않게

자는 동안 돌려놓는 도구라 두 가지가 다 위험합니다. 세 번째 주제에서 멈춰 있는 것도,
아무것도 저장 안 되는데 검색만 계속 태우는 것도 곤란합니다.

| 무슨 일 | 어떻게 |
|---|---|
| **대기열이 다 비었음** | 자동 이어가기가 꺼져 있으면 실행을 마칩니다. 켜져 있으면 큰 주제를 새로 만들어 계속 씁니다 |
| **AI가 주제를 거절** | **건너뜀**으로 표시하고 바로 다음 주제로. 재시도하지 않습니다 |
| 네이버 자동화 실패 | 설정한 횟수만큼 재시도하고, 실패하면 **화면을 찍어 두고** 다음 주제로 |
| 그 밖의 실패 | 설정한 횟수만큼 재시도한 뒤 **실패**로 두고 다음 주제로 |
| 사용량 한도 | **일시정지**합니다. 계속 돌려봐야 전부 실패하기 때문입니다 |
| **`claude` 로그인 만료** | **일시정지**합니다. 쓰던 주제는 실패가 아니라 **대기**로 되돌리므로, 다시 로그인하고 [이어서 실행]을 누르면 그 주제부터 이어집니다 |
| **검색이 실패함** (시간 초과, CLI 오류) | 주문을 접지 않습니다. 큰 주제로 글감을 직접 만들어 계속 씁니다. 대신 왜 실패했는지 로그에 남깁니다 |
| **주제를 못 찾음** | 두 번 연달아 빈손이면 **그 주문만** 접고 다음 주문으로 갑니다 (접을 때 화면에 진짜 원인을 같이 적습니다) |
| **찾아오는데 저장이 안 됨** | 목표의 두 배 넘게 찾아왔는데 저장이 안 되면 그 주문을 포기합니다 |

뒤의 두 항목이 중요합니다. 목표를 채울 때까지 도는 구조라서, 네이버 로그인이 풀려
글이 전부 실패하면 "찾아오고 → 실패하고 → 다시 찾아오고" 를 끝없이 반복하게 됩니다.
주제만 늘고 글은 하나도 안 늘어나는 상태라 거기서 멈춥니다.

**멈추는 단위는 대기열 전체가 아니라 주문 하나입니다.**

**어떤 경우에도 글 자체는 `data/posts/` 에 남습니다.** 네이버 저장이 실패해도
`preview.html` 을 열어 전체를 복사하면 에디터에 그대로 붙여넣을 수 있습니다.

## 자료 조사 (웹 검색)

주제를 고른 뒤에도 글을 쓰기 전에 **주제마다 다시 검색**합니다. 발굴 단계의 검색은
"무엇에 대해 쓸지" 를 정하려는 것이고, 여기 검색은 "그 글에 무슨 수치를 넣을지" 를
정하려는 것이라 목적이 다릅니다.

**조사와 집필을 두 번의 호출로 나눕니다.**

1. **조사** — 검색 도구를 켜고 사실과 출처 URL 만 모읍니다 (글은 쓰지 않습니다)
2. **집필** — 검색 도구를 끄고, 모아온 자료만 보고 글을 씁니다

한 번에 시키지 않는 이유가 있습니다. 도구를 쓰면서 동시에 엄격한 JSON 을 뱉게 하면
검색 결과를 설명하는 산문이 앞뒤로 붙어 파싱이 자주 깨집니다.
나눠서 얻는 것이 하나 더 있습니다. 조사 결과가 `research.json` 으로 남아서
발행 전에 **이 글이 무엇을 근거로 쓰였는지** 사람이 직접 확인할 수 있습니다.

조사 단계에서 챙기는 것들:

- 오늘 날짜를 알려줘 "최신"의 기준을 잡습니다
- 공식 출처(정부기관, 공공기관, 주관 기관)를 민간 블로그보다 우선합니다
- 중요한 수치는 두 곳 이상에서 교차 확인하게 합니다
- **지어낸 URL 을 걸러냅니다.** `example.com` 이나 점 없는 호스트는 버립니다
- 확인하지 못한 내용은 `unverified` 로 따로 받아, 본문에서 단정하지 않게 합니다
- **검색이 실제로 몇 번 돌았는지 셉니다.** 0회면 "검색했다고 말만 한" 결과라서 경고를 띄웁니다

마지막 항목은 발굴 단계에도 똑같이 있습니다. 검색 0회로 고른 주제는 최신 정보가
아니라 모델이 아는 내용이라, 이 도구의 목적 자체가 무너집니다.

출처는 글 맨 끝에 **제목과 발행처, 날짜만** 적습니다. 주소는 넣지 않습니다.

네이버 에디터는 `<a>` 태그가 없어도 **본문 글자 안의 주소를 스스로 찾아내
링크 카드로 갈아끼웁니다.** 특히 문단 끝에 주소가 오면 그 문단을 통째로
카드로 바꿔서, 앞에 적어둔 제목과 발행처가 사라지고 기사 카드만 남습니다.
실제로 "제목 + 기사 카드 하나" 만 있는 글이 저장되는 사고의 원인이었습니다.
그래서 에디터로 나가는 마지막 길목에서 본문의 모든 주소를 호스트만 남기고
걷어냅니다. 전체 주소는 `research.json` 과 `preview.html` 에 그대로 남아
있으니 발행 전에 원문을 대조하는 데는 지장이 없습니다.

> **비용과 시간이 늡니다.** 글 하나에 조사 1회 + 집필 1회, 여기에 주제 발굴이
> 몇 건에 한 번씩 붙습니다. 게다가 네이버는 에디터에 옮겨 적는 데만 1~2분 걸리고
> 글 사이 대기(30~90초)도 있습니다. **글 하나에 5~7분** 잡으시면 됩니다.

> **조사해 왔다고 사실이 보장되지는 않습니다.** 검색 결과에도 틀린 내용이 있고,
> 모델이 자료를 잘못 읽을 수도 있습니다. 그래서 이 프로그램은 발행하지 않고 임시저장만 합니다.
> 미리보기 맨 위의 **확인하지 못한 내용**부터 보시고, 수치는 원문에서 대조하세요.

## 품질 규칙을 어떻게 지키는가

규칙을 프롬프트에 적어 넣는 것만으로는 부족합니다.
모델이 안 지킨 채로 나와도 그대로 저장되기 때문입니다.

그래서 `src/content/quality.js` 한 곳에 규칙을 정의하고, **같은 정의에서 두 가지를 만들어 냅니다.**

1. 글을 쓰기 전 프롬프트에 들어갈 **지시문**
2. 나온 글을 실제로 검사하는 **검사기**

검사에 걸리면 걸린 항목만 짚어 다시 쓰게 하고(기본 1회), 통과할 때까지 확인합니다.
지시와 검사가 한 파일에 묶여 있어서 따로 놀 수가 없습니다.

| 규칙 | 검사 내용 |
|---|---|
| 분량 | 공백 제외 1,800자 이상 (설정에서 조정) |
| 종결어미 | `~습니다`, `~입니다` 형태가 85% 이상. `~함`, `~임` 개조식은 발견 즉시 실패 |
| 소제목 구조 | 큰 소제목 3개 이상 + 세부 소제목 1개 이상 |
| 선정 기준 | 서두에 "무엇을 기준으로 골랐는지" 단락이 있는지 |
| 비교 표 | 2행 2열 이상의 표가 최소 1개 |
| 불렛 포인트 | 목록이 최소 1개 |
| 항목별 상세 | 항목형 글에서 각 항목마다 세부 소제목 3개 이상 |
| 서두 인사말 금지 | "안녕하세요", "이번 포스팅에서는" 으로 시작하지 않는지 |
| 기호·이모지 | 별표, 화살표, 이모지 등 장식 기호가 본문에 있는지 |
| **태그** | **검색어로 쓸 태그 3개 이상. 네이버 태그에는 공백을 못 넣으므로 붙여 씁니다** |
| 마무리 | 요약과 독려가 담긴 마무리 단락이 충분한지 |

규칙 자체는 머니러시의 **구글 애드센스 승인 기준**을 그대로 가져왔습니다.
"깊이 있고 구조화된 정보성 글" 을 만드는 조건이라 네이버에서도 똑같이 유효하고,
네이버 검색(C-Rank·DIA)도 결국 같은 것을 봅니다. 굵게 표시한 **태그** 규칙만 새로 붙였습니다.

결과는 작업표의 **품질** 열에 `11/11` 처럼 표시되고, 마우스를 올리면 항목별 판정이 보입니다.
`5번 칸 > 끝내 못 고치면 저장하지 않기` 를 켜면 규칙을 못 지킨 글은 아예 올리지 않습니다.

> 검사기는 형식을 봅니다. **사실관계는 사람이 확인해야 합니다.**

## 주제에 따라 글 모양이 달라집니다

| 주제 예시 | 모양 | 어떻게 쓰는가 | 호출 횟수 |
|---|---|---|---|
| `국가기술자격증 TOP 5` | 항목별 상세형 | 항목마다 섹션 1개 + 세부 소제목 5개 | 1회 |
| `겨울 캠핑 장비 추천` | 항목별 상세형 | 개수는 AI가 정합니다 (5개 내외) | 1회 |
| `전국 대학교 순위` | 대형 비교표형 | **개수를 안 써도 100위까지** 뽑습니다 | 3회 |
| `전세 계약 전 확인할 서류` | 정보 정리형 | 소제목 중심 + 세부 소제목 | 1회 |

순위 글을 100위까지 채우는 방법, 뒤 구간을 지방·소규모까지 넓히는 지시,
중복 이름을 버리고 빠진 번호를 다시 채우는 부분은 머니러시와 같습니다.

### 목표를 못 채워도 순위는 반드시 매깁니다

`TOP 50` 인데 31개밖에 못 찾는 일은 흔합니다. 그때 **빈 번호를 남기지 않습니다.**
찾은 31개에 **1위부터 31위까지 다시 번호를 매겨** 온전한 표로 냅니다.
(예전에는 모델이 매긴 번호를 그대로 써서 "1~20위, 그리고 35~45위" 처럼
중간이 뚝 끊긴 표가 나왔습니다)

모자란 사실은 숨기지 않고 표 아래에 밝힙니다.

> 50개를 목표로 했으나 확인 가능한 범위에서 31개를 정리해 1위부터 31위까지 실었습니다.

### 근거가 없다고 글을 거르지 않습니다

이 도구가 다루는 주제는 대부분 공식 통계가 없습니다(대학 순위, 연봉 순위,
성과급 순위…). 그때마다 "근거가 없어 못 쓰겠다" 로 접으면 쓸 수 있는 글이
거의 남지 않습니다. 그래서 **과거 자료와 통념, 합리적인 추정으로 씁니다.**

대신 선을 하나 긋습니다. **근거 수준을 밝히면 추정으로 써도 되고,
공식 기관이 발표한 것처럼 꾸미면 안 됩니다.**

| | |
|---|---|
| 안 됩니다 | "교육부 2026년 발표에 따르면 취업률 87.3%입니다" |
| 됩니다 | "취업률이 높은 편으로 알려져 있으나, 학과와 연도에 따라 차이가 큽니다" |

그래도 AI 가 거절하면 **조건을 바꿔 한 번 더 요청**합니다. 두 번째에도
거절하면 그 주제만 건너뜁니다.

100행짜리 표를 네이버 에디터에 넣는 것은 또 다른 문제입니다.
한 덩어리로 붙여넣으면 에디터가 표를 통째로 흘려버리기 때문에,
**한 번에 → 20행씩 조각내서 → 그림으로 그려 업로드** 순으로 내려갑니다.
마지막 단계까지 가면 글자를 선택할 수는 없지만, 표가 사라지지는 않습니다.

## 썸네일 (선택)

기본값은 **HTML로 만드는 단색 썸네일**입니다. 추가 비용이 없습니다.
이미지 생성 API 를 붙이면 두 가지 방식 중에 고를 수 있습니다.

| 방식 | 어떻게 | 한글 |
|---|---|---|
| **통째로 그리기** (`full`, 기본) | 제목·띠·뱃지까지 그림 안에 다 그립니다 | 이미지 모델이 그립니다. 가끔 뭉개집니다 |
| **배경만 그리기** (`overlay`) | 글자 없는 배경만 그리고 한글은 HTML 이 얹습니다 | 브라우저가 그려서 **절대 안 깨집니다** |

두 방식 모두 **가장 싼 모델부터** 씁니다. 만들고 나서 글자가 제대로 나왔는지 확인하고,
실제로 깨졌을 때만 한 단계 올라갑니다.

```
1) 가장 싼 모델로 그린다  →  글자 확인 통과  →  끝            ← 대부분 여기서 끝납니다
2) 깨졌으면 같은(가장 싼) 모델로 한 번 더                       ← 그냥 운이 나빴을 수 있습니다
3) 그래도 깨지면 다음으로 싼 모델로 한 번                       ← 이 모델이 한글을 못 그리는 것입니다
4) 그래도 깨지면 HTML 썸네일                                    ← 한글이 절대 안 깨집니다
```

[aistudio.google.com](https://aistudio.google.com/apikey) 에서 키를 발급받아
**6번 설정**에 넣고 **[이미지 API 테스트]** 를 누르면 실제 문구가 박힌 그림 한 장과
모델 목록이 나옵니다. 가장 싼 등급 기준 장당 $0.03 안팎입니다.

## 설치와 실행

```bash
npm install
npm run setup      # claude CLI · 크로미움 · 저장된 세션 확인 (선택)
npm start          # → http://localhost:3000
```

3000번 포트를 다른 프로그램이 쓰고 있으면 3001, 3002... 로 알아서 옮겨 엽니다.
실제 주소는 창에 찍히는 `대시보드가 열렸습니다 → ...` 줄을 보세요.

포트를 직접 정하고 싶다면:

```powershell
# 윈도우 (PowerShell)
$env:PORT=8080
npm start
```

```bash
# 맥 · 리눅스
PORT=8080 npm start
```

코드를 고쳤다면 자체 점검을 먼저 돌려보세요.

```bash
npm run check          # AI 호출도 브라우저도 없이. 몇 초면 끝납니다
npm run check:editor   # 가짜 에디터를 띄워 붙여넣기 경로만 확인 (네이버 접속 없음)
```

`npm run check` 는 모든 모듈을 실제로 불러오고 품질 검사 · 붙여넣기 HTML ·
조각내기 · 표 쪼개기 · 주제 발굴 · 실행 루프 판단까지 한 번씩 돌려 봅니다.

`npm run check:editor` 는 브라우저가 있어야 볼 수 있는 것을 봅니다.
**에디터 구조를 바꿔 가며** 붙여넣기를 돌려서, 커서를 잡는 코드가 특정 구조를
가정하고 있지 않은지 확인합니다. 실제로 `.se-main-container` 안에
`[contenteditable="true"]` 가 있다고 가정한 코드 때문에 글은 다 써 놓고
한 건도 저장하지 못한 적이 있어서 생긴 검사입니다.

## 그 밖의 설정 항목

| 항목 | 설명 |
|---|---|
| 블로그 아이디 | 로그인하면 자동으로 채워집니다. 못 찾으면 직접 넣으세요 |
| 웹 검색으로 자료 모으기 | 끄면 검색 없이 빠르게 씁니다. **주제 발굴은 이 설정과 무관하게 항상 검색합니다** |
| 검색 횟수 상한 | 조사 단계의 상한. 기본 5회 |
| 글 끝에 출처 목록 붙이기 | 근거를 밝히는 글은 검색에서도 유리합니다 |
| 최소 분량 (공백 제외) | 권장값 1,800자 |
| 소제목 개수 | 규칙상 3~4개 |
| 보정 재요청 횟수 | 검사에 걸렸을 때 다시 쓰게 할 횟수. 호출이 늘어나므로 1회 권장 |
| 끝내 못 고치면 저장하지 않기 | 켜면 규칙 미준수 글을 아예 올리지 않습니다 |
| 사용할 AI 모델 | 드롭다운에서 고릅니다. Sonnet 5 권장 |
| 말투 / 독자 | 프롬프트에 그대로 반영됩니다 |
| 글 끝에 #태그 줄 붙이기 | 네이버 검색 유입의 실제 통로입니다 |
| 순위 글 목표 개수 | 개수를 안 쓴 순위 주제를 몇 위까지 뽑을지. 기본 100 |
| 썸네일 스타일 / 크기 | `auto`(AI 선택) · `minimal`(권장) · `bold` · `gradient` · `editorial` |
| 썸네일을 본문에 넣기 | 도입부 바로 뒤에 들어가고, 네이버가 이것을 대표 이미지로 씁니다 |
| **브라우저 창 숨기기** | 헤드리스 실행. **네이버는 창을 띄우는 편이 더 안전합니다** |
| **자동화 실패 시 화면 캡처** | 무엇이 막혔는지 볼 수 있는 유일한 단서입니다. 켜두세요 |
| 글 사이 대기 | 기본 30~90초 무작위. 연속 자동화를 완화합니다 |
| 재시도 횟수 | 실패한 주제를 자동으로 다시 시도하는 횟수 |
| 연속 실패 시 멈춤 | **0이면 멈추지 않고 끝까지** 갑니다 (기본) |

설정 파일에서만 조정 가능한 항목:

- `discover.region` — 어느 지역 독자 기준으로 찾을지 (기본 `한국`)
- `discover.timeoutMs` — 발굴 대기 시간 (기본 420초)
- `claude.command` — `claude` 실행 파일 경로 (PATH에 없을 때)
- `claude.timeoutMs` — AI 응답 대기 시간 (기본 420초)
- `run.chromiumPath` — 쓸 크롬/크로미움 경로 (환경변수 `CHROMIUM_PATH` 도 가능)
- `run.slowMoMs` — 브라우저 동작 사이 지연 (자동화를 눈으로 따라가며 고칠 때)
- `image.timeoutMs` — 이미지 생성 대기 시간 (기본 180초)

## 추가 지침 · 참고 예시

3번 칸의 **추가 지침**은 프롬프트의 맨 앞과 맨 끝에 두 번 들어갑니다.
한 줄에 하나씩 쓰면 더 잘 지킵니다.

```
수도권 기준으로 설명할 것
비용은 대략적인 범위로만 언급할 것
마지막에 준비 체크리스트를 넣을 것
```

**필수 준수 규칙이 지침보다 우선**합니다. "세 줄로 짧게 써줘" 같은 지침이
규칙을 이겨버리면 이 프로그램의 존재 이유가 사라지기 때문입니다.

**참고 예시 글**을 올리면 AI 가 문체·문단 길이·소제목 방식을 참고합니다.
내용을 베끼지는 않고, 필수 규칙과 충돌하면 규칙을 따릅니다.

## 안전장치

- **발행하지 않습니다.** 에디터에서 누르는 버튼은 글자가 정확히 "저장" 인 것뿐입니다.
  발행 버튼은 선택자 목록에 아예 들어 있지 않습니다.
- **비밀번호를 받지 않습니다.** 네이버 로그인은 사용자가 브라우저 창에서 직접 합니다.
  이 프로그램은 아이디와 비밀번호를 입력받지도, 저장하지도, 어디로 보내지도 않습니다.
- **이미지 API 키를 밖으로 내보내지 않습니다.** `data/settings.json`(권한 600)에만 저장되고,
  대시보드로 내려보내는 설정에서는 값을 빼고 "채워짐" 여부만 보냅니다.
- **본문에 태그를 주입할 수 없습니다.** AI 응답은 전부 이스케이프하고 `<b>` 강조만 되살립니다.
  발굴해 온 주제와 근거 주소도 마찬가지로, 화면에 그릴 때 전부 이스케이프합니다.
- **끝없이 돌지 않습니다.** 주제를 못 찾거나, 찾아와도 저장이 안 되면 멈춥니다.
- **글은 어떤 경우에도 남습니다.** 네이버 저장을 시도하기 전에 `data/posts/` 에 먼저 씁니다.

## 알아두실 점

- 발행이 아니라 **임시저장**만 합니다. 글의 사실관계와 최종 품질은 사람이 확인하고 발행하세요.
  **주제를 AI가 골랐다고 해서 확인을 덜 해도 되는 것이 아닙니다.** 오히려 더 봐야 합니다.
- 짧은 시간에 많은 글을 자동으로 올리면 네이버가 연속 자동화로 볼 수 있습니다.
  기본 대기 시간(30~90초)을 너무 줄이지 마시고, 한 번에 처리하는 양도 나눠서 돌리시길 권합니다.
- 네이버 검색 노출은 글 품질만으로 결정되지 않습니다. 블로그 지수, 주제 일관성, 발행 주기,
  체류 시간 등도 함께 봅니다. 이 프로그램은 그중 **글 품질 부분**을 돕습니다.
- 관심도 점수는 **AI가 매긴 추정치**입니다. 실제 검색량 데이터가 아닙니다.
  주제를 고르는 순서를 정하는 용도로만 쓰세요.
- 에디터가 바뀌면 자동화가 깨질 수 있습니다. 대부분 `src/naver/selectors.js` 만 고치면 됩니다.
