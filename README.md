# 인포러시 (inforush)

엑셀에서 복사한 주제 목록을 붙여넣으면, AI가 주제마다 **정보성 글**과 썸네일을 만들어
**네이버 블로그에 임시저장**해 주는 로컬 대시보드입니다.

워드프레스용 [워프러시](https://github.com/jettyy/wordpress)를 그대로 따르되,
**글을 올리는 곳만 네이버 블로그로 바꿨습니다.** 글을 쓰는 방식, 지켜야 할 규칙,
자료 조사, 품질 검사, 순위표를 채우는 방법은 모두 같습니다.

- 글 생성: `claude -p` (Claude Code CLI 헤드리스 모드) → **구독 요금제 그대로 사용**, 토큰 종량 과금 없음
- 자료 조사: 글을 쓰기 전에 **웹 검색으로 최신 자료와 기사를 찾아** 그 내용만 근거로 씀. 출처는 글 끝에 붙음
- 품질 준수: 분량·문체·표·구조를 **프로그램이 직접 검사**하고, 어긋나면 그 항목만 짚어 다시 쓰게 함
- 네이버 접속: **Playwright 로 띄운 실제 브라우저.** 로그인은 사용자가 그 창에서 직접 함
- 본문 넣는 법: 서식을 살린 HTML 을 **조각으로 나눠 붙여넣기.** 표는 따로, 실패하면 그림으로
- 순위 글: `TOP100` 은 물론 개수를 안 쓴 `전국 대학 순위` 도 **100위까지** 뽑음
- 썸네일: 원하면 **이미지 API가 제목·띠·뱃지까지 통째로** 그립니다. 언제나 가장 싼 모델부터 씁니다
- 결과물: 네이버 임시저장 + `preview.html`(그대로 복사해 붙여넣을 수 있는 본문) + `post.md`
- 발행은 하지 않습니다. **임시저장까지만** 하고, 사실 확인과 발행은 사람이 합니다.

## 워프러시(워드프레스)와 달라진 점

| | 워프러시 (워드프레스) | 인포러시 (네이버) |
|---|---|---|
| 접속 | REST API + 응용 프로그램 비밀번호 | **Playwright 로 띄운 실제 브라우저** |
| 로그인 | 비밀번호를 프로그램이 보관 | **사용자가 창에서 직접 로그인**. 비밀번호를 프로그램이 만지지 않음 |
| 본문 넣는 법 | API 로 한 번에 전송 | **에디터에 조각으로 나눠 붙여넣기** |
| 본문 형식 | 구텐베르크 블록 마크업 | **인라인 style 을 박은 HTML** (에디터가 색을 물려받지 않게) |
| 소제목 | `<h2>` + `<h3>` | 굵고 큰 **문단**으로 직접 그림 (에디터가 제목 태그를 갈아끼움) |
| 표 | API 로 보내면 끝 | **붙여넣기 → 조각내기 → 그림** 3단계로 반드시 넣음 |
| 대표 이미지 | 미디어 API 로 지정 | 도입부 뒤 첫 이미지가 **자동으로 대표 이미지**가 됨 |
| 분류 | 카테고리 ID 로 정확히 지정 | **발행할 때 사람이 고릅니다** (아래 "네이버라서 다른 것" 참고) |
| 태그 | 워드프레스 태그로 등록 | **글 끝에 `#태그` 줄**로 붙임 |
| 주소 | AI가 만든 영문 슬러그 | 네이버가 정함 (지정 불가) |
| 글 사이 대기 | 20~60초 | **30~90초** (네이버는 연속 자동화에 더 민감합니다) |
| 실행 위치 | 어디서나 (API 만 되면 됨) | **사용자 PC** (로그인 창이 필요합니다) |

## 왜 브라우저로 하는가

네이버에는 블로그 글쓰기 공개 API 가 없습니다. 그래서 실제 브라우저를 띄워
스마트에디터 ONE 에 사람이 하듯 옮겨 적는 방법밖에 없습니다.
이 방식은 워드프레스의 REST API 보다 느리고 잘 깨지므로, 깨지는 자리마다 대비를 넣었습니다.

| 깨지는 자리 | 대비 |
|---|---|
| 에디터 클래스 이름이 바뀜 | 선택자를 `src/naver/selectors.js` 한 곳에 후보 여러 개로 모아 둠. 자동화가 깨지면 대부분 여기만 고치면 됩니다 |
| 글쓰기 주소가 안 먹힘 | 주소 3개를 차례로 시도하고, 그래도 안 되면 블로그 화면의 글쓰기 버튼을 직접 누름 |
| 붙여넣기 거절 | 합성 paste → 실제 클립보드(Ctrl+V) → 평문 타이핑 순으로 내려감 |
| 표가 통째로 사라짐 | 한 번에 → 20행씩 조각내서 → **표를 그림으로 그려 파일 업로드** |
| 글자가 다 회색으로 나옴 | 모든 문단과 셀에 글자색을 직접 박음 (비우면 앞 블록 색을 물려받습니다) |
| 문단이 앞 문단에 들러붙음 | 조각마다 맨 앞에 빈 문단을 하나 붙여 그게 대신 합쳐지게 함 |
| 가운데 정렬로 들어감 | 저장 직전에 본문 전체를 왼쪽 정렬로 한 번에 맞춤 |
| 무엇이 막혔는지 모름 | 실패한 순간의 화면을 `data/screenshots/` 에 저장하고 경로를 작업표에 남김 |

표가 실제로 들어갔는지는 **에디터 안의 `<table>` 개수를 세어** 확인합니다.
"글자가 좀 늘었나" 만 보면 100행짜리 표가 통째로 잘려도 성공으로 치기 때문입니다.

## 네이버라서 다른 것 (미리 알아두실 점)

- **카테고리와 공개 설정은 지정하지 않습니다.** 네이버는 그 칸들이 [발행] 레이어 안에 있어서,
  임시저장만 하는 이 프로그램은 건드리지 않습니다. 발행하실 때 직접 고르세요.
- **태그는 발행창이 아니라 글 끝에 `#태그` 줄로 붙습니다.** 같은 이유입니다.
  발행할 때 태그 칸에 옮겨 넣으시면 검색 노출에 더 유리합니다.
- **대표 이미지는 따로 지정하지 않아도 됩니다.** 네이버는 글의 첫 번째 이미지를 대표로 씁니다.
  그래서 썸네일을 도입부 바로 뒤에 넣습니다.
- **글 주소는 정할 수 없습니다.** 워프러시의 영문 슬러그 기능은 여기서 뺐습니다.
- **임시저장한 글을 바로 여는 주소가 없습니다.** 작업표의 [임시저장 목록] 을 누르면
  글쓰기 화면이 열리고, 오른쪽 위 **[저장]** 을 누르면 저장된 글 목록이 나옵니다.
- **이 프로그램은 사용자 PC에서 실행해야 합니다.** 네이버 로그인에 실제 브라우저 창이 필요하고,
  세션도 사용자 PC에 저장되기 때문입니다.

## 자료 조사 (웹 검색)

모델이 아는 일반론만으로 쓴 글은 수치가 두루뭉술하거나 아예 틀립니다.
그래서 글을 쓰기 전에 **실제로 웹 검색을 해서** 사실과 출처를 먼저 모읍니다.

**조사와 집필을 두 번의 호출로 나눕니다.**

1. **조사** — 검색 도구를 켜고 사실과 출처 URL 만 모읍니다 (글은 쓰지 않습니다)
2. **집필** — 검색 도구를 끄고, 모아온 자료만 보고 글을 씁니다

한 번에 시키지 않는 이유가 있습니다. 도구를 쓰면서 동시에 엄격한 JSON 을 뱉게 하면
검색 결과를 설명하는 산문이 앞뒤로 붙어 파싱이 자주 깨집니다.
나눠서 얻는 것이 하나 더 있습니다. 조사 결과가 `research.json` 으로 남아서
발행 전에 **이 글이 무엇을 근거로 쓰였는지** 사람이 직접 확인할 수 있습니다.

조사 단계에서 챙기는 것들:

- 오늘 날짜를 알려줘 "최신"의 기준을 잡습니다
- 공식 출처(정부기관, 공공기관, 주관 기관)를 민간 블로그보다 우선합니다
- 중요한 수치는 두 곳 이상에서 교차 확인하게 합니다
- **지어낸 URL 을 걸러냅니다.** `example.com` 이나 점 없는 호스트는 버립니다
- 확인하지 못한 내용은 `unverified` 로 따로 받아, 본문에서 단정하지 않게 합니다
- **검색이 실제로 몇 번 돌았는지 셉니다.** 0회면 "검색했다고 말만 한" 결과라서 경고를 띄웁니다

출처는 글 맨 끝에 붙지만, **링크가 아니라 글자로** 적습니다.
네이버 에디터는 붙여넣은 링크를 링크 카드로 부풀려 넣고,
외부 링크가 여러 개 붙은 글은 검색에서 불리하게 볼 수 있기 때문입니다.
주소를 글자로 남겨 두면 읽는 사람이 원문을 찾아갈 수 있으면서 그런 위험은 지지 않습니다.

> **비용과 시간이 늡니다.** 검색이 붙으면 글 하나에 3~5분, 호출이 2회로 늘어납니다.
> 급하게 많이 돌려야 한다면 4번 칸에서 자료 조사를 끄면 됩니다. 대신 최신 수치는 못 씁니다.

> **조사해 왔다고 사실이 보장되지는 않습니다.** 검색 결과에도 틀린 내용이 있고,
> 모델이 자료를 잘못 읽을 수도 있습니다. 그래서 이 프로그램은 발행하지 않고 임시저장만 합니다.
> 미리보기 맨 위의 **확인하지 못한 내용**부터 보시고, 수치는 원문에서 대조하세요.

## 품질 규칙을 어떻게 지키는가

이 프로그램의 핵심입니다. 규칙을 프롬프트에 적어 넣는 것만으로는 부족합니다.
모델이 안 지킨 채로 나와도 그대로 저장되기 때문입니다.

그래서 `src/content/quality.js` 한 곳에 규칙을 정의하고, **같은 정의에서 두 가지를 만들어 냅니다.**

1. 글을 쓰기 전 프롬프트에 들어갈 **지시문**
2. 나온 글을 실제로 검사하는 **검사기**

검사에 걸리면 걸린 항목만 짚어 다시 쓰게 하고(기본 1회), 통과할 때까지 확인합니다.
지시와 검사가 한 파일에 묶여 있어서 따로 놀 수가 없습니다.

| 규칙 | 검사 내용 |
|---|---|
| 분량 | 공백 제외 1,800자 이상 (설정에서 조정) |
| 종결어미 | `~습니다`, `~입니다` 형태가 85% 이상. `~함`, `~임` 개조식은 발견 즉시 실패 |
| 소제목 구조 | 큰 소제목 3개 이상 + 세부 소제목 1개 이상 |
| 선정 기준 | 서두에 "무엇을 기준으로 골랐는지" 단락이 있는지 |
| 비교 표 | 2행 2열 이상의 표가 최소 1개 |
| 불렛 포인트 | 목록이 최소 1개 |
| 항목별 상세 | 항목형 글에서 각 항목마다 세부 소제목 3개 이상 (상세 설명 / 자격 요건 / 활용 분야 / 장단점 / 준비 팁) |
| 서두 인사말 금지 | "안녕하세요", "이번 포스팅에서는", "알아보겠습니다" 로 시작하지 않는지 |
| 기호·이모지 | 별표, 화살표, 이모지 등 장식 기호가 본문에 있는지 |
| **태그** | **검색어로 쓸 태그 3개 이상. 네이버 태그에는 공백을 못 넣으므로 붙여 씁니다** |
| 마무리 | 요약과 독려가 담긴 마무리 단락이 충분한지 |

규칙 자체는 워프러시의 **구글 애드센스 승인 기준**을 그대로 가져왔습니다.
"깊이 있고 구조화된 정보성 글" 을 만드는 조건이라 네이버에서도 똑같이 유효하고,
네이버 검색(C-Rank·DIA)도 결국 같은 것을 봅니다. 굵게 표시한 **태그** 규칙만 새로 붙였습니다.

결과는 작업표의 **품질** 열에 `11/11` 처럼 표시되고, 마우스를 올리면 항목별 판정이 보입니다.
`5번 칸 > 끝내 못 고치면 저장하지 않기` 를 켜면 규칙을 못 지킨 글은 아예 올리지 않습니다.

> 검사기는 형식을 봅니다. **사실관계는 사람이 확인해야 합니다.**

## 주제에 따라 글 모양이 달라집니다

| 주제 예시 | 모양 | 어떻게 쓰는가 | 호출 횟수 |
|---|---|---|---|
| `국가기술자격증 TOP 5` | 항목별 상세형 | 항목마다 섹션 1개 + 세부 소제목 5개 | 1회 |
| `겨울 캠핑 장비 추천` | 항목별 상세형 | 개수는 AI가 정합니다 (5개 내외) | 1회 |
| `전국 대학교 순위` | 대형 비교표형 | **개수를 안 써도 100위까지** 뽑습니다 | 3회 |
| `유튜브 구독자 TOP100` | 대형 비교표형 | 표를 50행씩 나눠 받고, 대표 항목만 상세하게 | 3회 |
| `전세 계약 전 확인할 서류` | 정보 정리형 | 소제목 중심 + 세부 소제목 | 1회 |

13개 이상이면 항목마다 다섯 항목씩 쓰는 것이 현실적으로 불가능해서 표 중심으로 넘어갑니다.

### 순위를 100위까지 채우는 법

큰 순위표가 깨지는 지점은 늘 **뒤쪽**입니다. 상위권은 누구나 아는 이름으로 금방 차지만,
50번을 넘어가면 모델이 앞에서 쓴 이름을 다시 쓰거나 "이하 생략" 하고 멈춥니다.
그래서 구간마다 어디까지 넓혀야 하는지 명시적으로 알려줍니다.

| 구간 | 지시 |
|---|---|
| 앞 25% | (없음) |
| 25~50% | 수도권 밖과 중견 규모까지 넓히세요 |
| 50~75% | **지방과 덜 알려진 곳**까지, 광역시와 각 도 단위로 고르게 훑으세요 |
| 뒤 25% | **규모가 작거나 특수 목적인 곳**까지. "더 이상 없습니다" 라고 답하지 마세요 |

여기에 더해 이미 나온 이름을 프롬프트에 넣어 제외시키고, 돌아온 행의 **이름이 겹치면
버립니다.** 빠진 번호는 연속 구간으로 묶어 최대 2번 더 채웁니다.

100행짜리 표를 네이버 에디터에 넣는 것은 또 다른 문제입니다.
한 덩어리로 붙여넣으면 에디터가 표를 통째로 흘려버리기 때문에,
**한 번에 → 20행씩 조각내서 → 그림으로 그려 업로드** 순으로 내려갑니다.
마지막 단계까지 가면 글자를 선택할 수는 없지만, 표가 사라지지는 않습니다.

## 썸네일 (선택)

기본값은 **HTML로 만드는 단색 썸네일**입니다. 추가 비용이 없습니다.
이미지 생성 API 를 붙이면 두 가지 방식 중에 고를 수 있습니다.

| 방식 | 어떻게 | 한글 |
|---|---|---|
| **통째로 그리기** (`full`, 기본) | 제목·띠·뱃지까지 그림 안에 다 그립니다. 포스터형 썸네일 | 이미지 모델이 그립니다. 가끔 뭉개집니다 |
| **배경만 그리기** (`overlay`) | 글자 없는 배경만 그리고 한글은 HTML 이 얹습니다 | 브라우저가 그려서 **절대 안 깨집니다** |

두 방식 모두 **가장 싼 모델부터** 씁니다. 만들고 나서 글자가 제대로 나왔는지 확인하고,
실제로 깨졌을 때만 올라갑니다.

```
1) 가장 싼 모델로 그린다  →  글자 확인 통과  →  끝            ← 대부분 여기서 끝납니다
2) 깨졌으면 같은(가장 싼) 모델로 한 번 더                       ← 그냥 운이 나빴을 수 있습니다
3) 그래도 깨지면 다음으로 싼 모델로 한 번                       ← 이 모델이 한글을 못 그리는 것입니다
4) 그래도 깨지면 HTML 썸네일                                    ← 한글이 절대 안 깨집니다
```

쓰려면 [aistudio.google.com](https://aistudio.google.com/apikey) 에서 키를 발급받아
**6번 설정**에 넣고 **[이미지 API 테스트]** 를 눌러 실제 그림을 한 번 보세요.
모델 이름 칸은 **비워두면 자동**으로 가장 싼 것부터 씁니다.

## 사용 흐름

1. **네이버 로그인** — [네이버 로그인 창 열기]를 누르면 브라우저 창이 뜹니다.
   아이디·비밀번호(+2단계 인증)를 그 창에 직접 입력하세요.
   로그인이 확인되면 세션이 `data/browser-profile/` 에 저장되고, 다음부터는 재로그인이 필요 없습니다.
   블로그 아이디는 자동으로 찾지만, 못 찾으면 입력칸에 직접 넣어 주세요.
2. **주제 붙여넣기** — 엑셀에서 주제 열을 복사해 그대로 붙여넣습니다.
   한 줄에 주제 하나로 인식하고, 탭으로 나뉜 경우 첫 열만 씁니다.
   머리글(`주제`, `제목` 등)과 중복은 자동으로 걸러냅니다.
3. **지침 & 예시** — AI에게 꼭 지키게 할 내용을 적고, 참고할 예시 글을 올립니다.
4. **자료 조사 설정** — 검색을 켤지, 몇 번까지 할지, 출처를 붙일지 정합니다.
5. **품질 규칙 확인** — 최소 분량, 소제목 개수, 보정 횟수를 조정합니다.
6. **설정** — 모델, 독자, 썸네일, 대기 시간 등을 조정합니다.
7. **실행** — 주제를 하나씩 순서대로 처리합니다.
   진행 상황·품질 점검 결과·썸네일이 표에 실시간으로 표시됩니다.
8. **확인** — 네이버 글쓰기 화면 오른쪽 위 **[저장]** 목록에서 내용과 사실관계를 확인하고 발행하세요.

## 실패해도 멈추지 않습니다

주제 100개를 걸어놓고 자는 동안, 세 번째 주제에서 멈춰 있으면 곤란합니다.
그래서 기본값은 **한 주제가 안 되면 그냥 다음 주제로 넘어가는 것**입니다.

| 무슨 일 | 어떻게 |
|---|---|
| **AI가 주제를 거절** | **건너뜀**으로 표시하고 바로 다음 주제로. 재시도하지 않습니다 |
| 네이버 자동화 실패 | 설정한 횟수만큼 재시도하고, 실패하면 **화면을 찍어 두고** 다음 주제로 |
| 그 밖의 실패 | 설정한 횟수만큼 재시도한 뒤 **실패**로 두고 다음 주제로 |
| 사용량 한도 | 여기서만 **일시정지**합니다. 계속 돌려봐야 전부 실패하기 때문입니다 |

거절을 재시도하지 않는 이유가 있습니다. 같은 주제로 다시 물어보면 같은 대답이 옵니다.
거절은 대개 **주제가 사실이 아닌 것을 지어내라고 요구할 때** 나옵니다.
주제를 조금 바꾸면 대개 써집니다.

- `확인된 위험 신호` → `일반적으로 거론되는 특징`
- `상위 업종 랭킹` → `자주 언급되는 업종과 그 배경`

**어떤 경우에도 글 자체는 `data/posts/` 에 남습니다.** 네이버 저장이 실패해도
`preview.html` 을 열어 전체를 복사하면 에디터에 그대로 붙여넣을 수 있습니다.

## 설정 항목

| 항목 | 설명 |
|---|---|
| 블로그 아이디 | 로그인하면 자동으로 채워집니다. 못 찾으면 직접 넣으세요 |
| 웹 검색으로 자료 모으기 | 끄면 검색 없이 빠르게 씁니다. 대신 최신 수치와 일정은 못 씁니다 |
| 검색 횟수 상한 | 기본 5회. 많을수록 정확하지만 글 하나당 시간이 늡니다 |
| 글 끝에 출처 목록 붙이기 | 근거를 밝히는 글은 검색에서도 유리합니다 |
| 출처를 못 구하면 글을 쓰지 않기 | 켜면 검색이 막혔을 때 그 주제를 실패로 남깁니다 |
| 최소 분량 (공백 제외) | 권장값 1,800자 |
| 소제목 개수 | 규칙상 3~4개 |
| 보정 재요청 횟수 | 검사에 걸렸을 때 다시 쓰게 할 횟수. 호출이 늘어나므로 1회 권장 |
| 끝내 못 고치면 저장하지 않기 | 켜면 규칙 미준수 글을 아예 올리지 않습니다 |
| 서두에 선정 기준 밝히기 / 자주 묻는 질문 넣기 | 글의 정보성을 높이는 부분입니다 |
| 사용할 AI 모델 | 드롭다운에서 고릅니다. 목록에 없는 모델은 "직접 입력…"으로 |
| 말투 / 독자 | 프롬프트에 그대로 반영됩니다 (말투는 규칙을 벗어나면 검사에서 걸립니다) |
| 글 끝에 #태그 줄 붙이기 | 네이버 검색 유입의 실제 통로입니다 |
| 순위 글 목표 개수 | 개수를 안 쓴 순위 주제를 몇 위까지 뽑을지. 기본 100 |
| 썸네일 스타일 / 크기 | `auto`(AI 선택) · `minimal`(권장) · `bold` · `gradient` · `editorial` |
| 썸네일을 본문에 넣기 | 도입부 바로 뒤에 들어가고, 네이버가 이것을 대표 이미지로 씁니다 |
| 썸네일을 이미지 API로 만들기 / 만드는 방식 / 이미지 모델 | 위 "썸네일" 절 참고. 모델 칸은 **비우면 자동** |
| 썸네일에 이모지 허용 | 정보성 글에서는 꺼두는 편이 안전합니다 |
| **브라우저 창 숨기기** | 헤드리스 실행. **네이버는 창을 띄우는 편이 더 안전합니다** |
| **자동화 실패 시 화면 캡처** | 무엇이 막혔는지 볼 수 있는 유일한 단서입니다. 켜두세요 |
| 글 사이 대기 | 기본 30~90초 무작위. 연속 자동화를 완화합니다 |
| 재시도 횟수 | 실패한 주제를 자동으로 다시 시도하는 횟수 |
| 연속 실패 시 멈춤 | **0이면 멈추지 않고 끝까지** 갑니다 (기본) |

설정 파일에서만 조정 가능한 항목:

- `claude.command` — `claude` 실행 파일 경로 (PATH에 없을 때)
- `claude.timeoutMs` — AI 응답 대기 시간 (기본 420초)
- `run.chromiumPath` — 쓸 크롬/크로미움 경로 (환경변수 `CHROMIUM_PATH` 도 가능)
- `run.slowMoMs` — 브라우저 동작 사이 지연 (자동화를 눈으로 따라가며 고칠 때)
- `image.timeoutMs` — 이미지 생성 대기 시간 (기본 180초)

## 추가 지침

대시보드 **3번 칸**에 쓰는 내용입니다. 입력하면 자동으로 저장됩니다.
프롬프트의 **맨 앞**과 **맨 끝**에 두 번 들어갑니다. 한 줄에 하나씩 쓰면 더 잘 지킵니다.

```
수도권 기준으로 설명할 것
비용은 대략적인 범위로만 언급할 것
마지막에 준비 체크리스트를 넣을 것
```

워프러시와 같이, **필수 준수 규칙이 지침보다 우선**합니다.
"세 줄로 짧게 써줘" 같은 지침이 규칙을 이겨버리면 이 프로그램의 존재 이유가 사라지기 때문입니다.
말투·분량·구조 외의 요구는 그대로 반영됩니다.

AI 는 지침을 어떻게 반영했는지 `guidelineCheck` 로 스스로 보고하고,
그 내용이 작업표의 **지침 확인** 배지(마우스를 올리면 보입니다)와 진행 로그에 남습니다.

## 참고 예시 글

"이런 식으로 써줘" 하고 보여줄 글을 올리면 AI 가 문체·문단 길이·소제목 방식을 참고합니다.
내용을 베끼지는 않고, 필수 규칙과 충돌하면 규칙을 따릅니다.

- `txt` / `md` / `html` / `csv` / `json` 파일을 첨부하거나 직접 붙여넣습니다
- 여러 개 올려두고 체크박스로 켜고 끌 수 있습니다
- 한 개당 최대 20,000자, 전체 합쳐 24,000자까지 프롬프트에 들어갑니다

## 속도와 토큰을 아끼려면

`claude -p` 는 **호출 한 번당** CLI 자체 시스템 프롬프트로만 3만 토큰 넘게 씁니다.
따라서 글자 수보다 **호출 횟수**가 비용을 좌우합니다.

| 설정 | 권장값 | 효과 |
|---|---|---|
| 사용할 AI 모델 | Sonnet 5 | 1,800자 + 표 + 항목별 상세를 한 번에 채우면서 속도도 쓸 만합니다 |
| 자료 조사 | 필요할 때만 켜기 | 검색이 붙으면 호출이 2회로 늘고 글 하나에 3~5분 걸립니다 |
| 검색 횟수 상한 | 4~5 | 더 올려도 출처가 크게 늘지 않고 시간만 늡니다 |
| 보정 재요청 횟수 | 1 | 0으로 두면 호출이 줄지만 미준수 글이 그대로 올라갑니다 |
| 최소 분량 | 1,800 | 더 올리면 출력 토큰과 시간이 함께 늡니다 |
| 주제의 항목 수 | 12 이하 | 13개부터는 표를 나눠 받느라 호출이 늘어납니다 |

다만 **네이버는 AI 호출보다 브라우저 쪽이 느립니다.** 글 하나를 에디터에 옮겨 적는 데만
1~2분 걸리고, 글 사이 대기(30~90초)도 있습니다. 100편이면 밤새 돌린다고 보시면 됩니다.

## 안전장치

- **발행하지 않습니다.** 에디터에서 누르는 버튼은 글자가 정확히 "저장" 인 것뿐입니다.
  발행 버튼은 선택자 목록에 아예 들어 있지 않습니다.
- **비밀번호를 받지 않습니다.** 네이버 로그인은 사용자가 브라우저 창에서 직접 합니다.
  이 프로그램은 아이디와 비밀번호를 입력받지도, 저장하지도, 어디로 보내지도 않습니다.
- **이미지 API 키를 밖으로 내보내지 않습니다.** `data/settings.json`(권한 600)에만 저장되고,
  대시보드로 내려보내는 설정에서는 값을 빼고 "채워짐" 여부만 보냅니다.
- **본문에 태그를 주입할 수 없습니다.** AI 응답은 전부 이스케이프하고 `<b>` 강조만 되살립니다.
- **글은 어떤 경우에도 남습니다.** 네이버 저장을 시도하기 전에 `data/posts/` 에 먼저 씁니다.

## 알아두실 점

- 발행이 아니라 **임시저장**만 합니다. 글의 사실관계와 최종 품질은 사람이 확인하고 발행하세요.
- 짧은 시간에 많은 글을 자동으로 올리면 네이버가 연속 자동화로 볼 수 있습니다.
  기본 대기 시간(30~90초)을 너무 줄이지 마시고, 한 번에 처리하는 양도 나눠서 돌리시길 권합니다.
- 네이버 검색 노출은 글 품질만으로 결정되지 않습니다. 블로그 지수, 주제 일관성, 발행 주기,
  체류 시간 등도 함께 봅니다. 이 프로그램은 그중 **글 품질 부분**을 돕습니다.
- 에디터가 바뀌면 자동화가 깨질 수 있습니다. 대부분 `src/naver/selectors.js` 만 고치면 됩니다.
